# 硬件与操作系统接口边界

> 更新：2026-11-12。执行器 HAL 已通过 `er_devices` 绑定组件接入原生 runner 和 WASM 桥接；其他 HAL 仍为契约草案，没有完成具体 OS/BSP 实现。

`include/er/hal.h` 是平台边界的最小定义。实时核心只依赖接口和数据契约，不包含 MCU SDK、RTOS 头文件、总线寄存器或具体引脚。计划由 FreeRTOS、RT-Thread、Zephyr、Linux 和裸机端口实现对应接口。

## 时钟与实时约束

`er_hal_clock_t.now_us()` 必须是单调递增的 64 位时间，不能使用会校时的墙上时钟。控制任务自己负责周期调度；接口函数必须在预算内返回，不能在实时路径执行内存分配、文件系统、网络等待或字符串格式化。

## 传感器

传感器驱动通过 `er_hal_sensor_t.read()` 返回值及采样时间。`sample_us` 不得晚于调用方的 `now_us`，调用方根据数据年龄和范围决定是否接受。断线、CRC 错误、越界和超时返回明确错误码，不能用 0 伪装成有效值。

## 执行器

`er_hal_actuator_t` 用能力位表示设备支持的操作：

- 普通 PWM 舵机通常提供 `POSITION`，反馈能力可没有。
- 总线舵机通常提供位置、速度和反馈，并由 CAN/RS485 驱动实现。
- 智能电机驱动器可提供位置、速度、力矩和使能。
- 直接 PWM/FOC 驱动需要在本地驱动中完成 ADC、PWM 同步和硬件过流保护，再通过同一接口向上层暴露能力。

调用方必须先检查能力位；不支持的函数返回 `ER_HAL_ENOTSUP`。`enable(false)` 的实际安全含义（高阻、制动或保持）由设备驱动声明并在硬件验收中测量，不能仅由 API 名称推断。

## 存储、参数与 OTA

`er_hal_storage_t` 只抽象有界读、写和擦除。上层参数服务负责 CRC、双备份、版本迁移和磨损策略；OTA 服务负责镜像哈希、签名、A/B 元数据和断电恢复。存储操作不能直接从控制周期调用，应由系统服务任务执行。

## 看门狗

看门狗由系统服务配置，只有在控制任务心跳、故障状态和驱动响应都正常时才允许 `feed()`。控制任务失联时必须由独立硬件看门狗复位或进入硬件安全状态。

## 适配层验收

每个 OS/BSP 端口至少需要：单调时钟测试、超时测试、传感器断线测试、执行器禁能测试、存储掉电测试和看门狗失联测试。接口源码兼容不代表实时性兼容；周期抖动、禁能延迟和故障响应时间必须在目标硬件上分别实测。

## 当前绑定实现

`src/devices.c` 不依赖仿真：它复制 `er_hal_actuator_t` 接口表，通过 `ctx` 回调设备。闭环要求 `FEEDBACK | VELOCITY | ENABLE` 及对应回调，缺能力返回 `ER_HAL_ENOTSUP`；缺回调返回参数错误。静态实例由调用方持有，生命周期覆盖绑定期，重新绑定前先停止旧设备。

反馈读取保留最旧采样时间并检查有效期。写入或反馈错误锁存绑定故障，并尽力禁用所有轴；禁用失败仍需独立硬件保护。恢复需明确重绑定和运行时复位。多轴写入不是硬件原子事务，可能短暂部分成功。

`sim/actuator.c` 提供两种配置：有反馈模型支持位置、速度、反馈和使能；无反馈模型只声明位置和使能，读取反馈返回 `ENOTSUP` 且不改写输出，不能绑定到当前闭环核心。无反馈模型的内部位置仅用于仿真观察，不是设备上报。电流/扭矩未建模，反馈 effort 为 NaN，不用于位置控制。

## OS 与设备解耦是两条边界

当前完成的是设备绑定链路，不是完整 OSAL。通过 OSAL/设备契约编写的业务未来可连接 Linux 或 RTOS 实现；直接调用内核 API、ISR 或寄存器的代码仍需对应适配层。Linux 测试验证逻辑，不替代 MCU 调度、时序和电气测试。
