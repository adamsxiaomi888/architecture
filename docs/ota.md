# 量产 OTA 与系统服务方案

> 更新：2026-11-12。这是量产目标方案，不是已完成能力。`src/ota.c` 只有内存状态机、长度计数和验证回调；没有镜像写入、加密验证、持久化、Bootloader 或断电回滚。已知缺陷包括下载未绑定唯一槽、可覆盖待确认槽、激活时未复查版本。

## 总体原则

OTA、网络、日志、参数和诊断属于“系统服务域”；电机采样、控制计算、限位、故障锁存和 STO 属于“实时安全域”。系统服务域永远不能直接写 PWM、驱动器寄存器或 `er_runtime_t`，只能通过有界命令邮箱和受控的参数提交接口交互。升级期间实时域继续运行当前镜像；升级失败不能影响当前控制镜像。

推荐设备结构：Linux 主控负责模型、规划和远程管理，控制 MCU 运行 FreeRTOS/RT-Thread。Linux 和 MCU 都采用双镜像；MCU 的 bootloader 必须独立于应用，且能在应用损坏时保持电机禁能。

## A/B 镜像布局

```text
Bootloader（只读/受保护）
├── Image A：控制固件或 Linux 系统
├── Image B：备用固件或 Linux 系统
├── 持久化元数据：活动槽、尝试次数、确认标志、最低版本
└── 参数/标定区：双备份 + CRC + 单调版本
```

升级流程：下载到非活动槽 → 分块哈希和整体签名校验 → 检查产品型号、硬件版本、依赖协议和最低允许版本 → 写入元数据并设置“试运行” → 重启进入新槽 → 应用完成硬件自检、控制任务心跳和安全输出检查后写入确认标志。未在限定时间内确认，bootloader 自动回滚旧槽。元数据更新采用两阶段提交和掉电安全记录，不能只依赖一个擦写扇区。

## 安全校验与版本策略

- 发布包使用离线签名私钥；设备只内置公钥或证书链，私钥不进入设备和 CI 工作目录。
- 包含 manifest：产品/板型、镜像长度、SHA-256、签名、协议版本、依赖 bootloader 版本、构建 commit、SBOM 摘要和最低安全版本。
- 先验签再解压、写入和切换；哈希不匹配、签名无效、空间不足、硬件不兼容均拒绝安装。
- 防回滚使用 eFuse/安全存储中的单调计数器或受保护版本号。开发板可提供显式降级开关，量产设备关闭。
- OTA 传输可断点续传，但服务端和设备都必须按分块哈希验证；断电后从已验证分块继续。

## 与电机控制隔离

升级下载、解包、闪存擦写、TLS、日志上传不得运行在控制周期任务中。控制任务只处理固定长度、预分配的消息；其看门狗喂狗前必须确认周期、传感器、驱动器通信和故障状态均正常。升级请求进入 `PENDING` 状态后，设备先停止接收新运动任务，等待机构进入安全姿态并由实时域确认 `SAFE_TO_UPDATE`；否则只能下载，禁止切换或擦写活动控制镜像。

切换前必须：关闭执行器使能或进入硬件 STO、保存故障与位置摘要、停止上层动作、确认外部急停状态。bootloader 默认 GPIO 状态必须使驱动器禁能。升级过程中的复位、看门狗超时或掉电都应回到禁能状态。

## 看门狗、回滚和故障处理

使用独立硬件 watchdog，控制任务和系统服务任务分别报告心跳；服务域失效不能阻塞控制域。bootloader 维护新镜像启动尝试次数（建议 3 次）和确认超时（例如 30 秒，按产品评审调整）。以下任一条件触发回滚：启动自检失败、控制周期持续超限、关键传感器无效、通信初始化失败、应用未确认或 watchdog 复位。

回滚后保留失败槽的 manifest、复位原因和阶段码，供诊断读取；不要自动反复重试导致设备循环重启。远程平台应看到设备处于 `ROLLBACK_REQUIRED`，由人工或受控策略决定下一步。

## 参数、日志和远程运维

参数与固件分离：默认参数只读，标定参数双备份，写入顺序为新副本→CRC/签名→提交指针。参数变更需范围和机构状态校验，运动中拒绝改变安全相关限制。日志采用固定长度事件记录，实时线程只写事件码和数值，不格式化字符串；上传在服务域异步完成。远程命令必须带设备 ID、序列号、过期时间和权限，重复或过期命令拒绝。

## 发布和验证门禁

CI 固定工具链、链接脚本、配置和依赖，生成可追溯 SBOM。发布前执行签名验证、断电注入、下载中断、损坏包、回滚、看门狗复位、温度/电压边界及 STO 实测；在目标硬件上验证升级期间控制输出保持安全。只有通过 HIL 和小批量老化后，才允许扩大 OTA 灰度范围。每个设备记录硬件版本、活动槽、镜像版本、构建 commit、参数版本和最后一次升级结果。
