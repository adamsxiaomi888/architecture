# 量产落地清单

## 阶段

1. **样机**：Linux 仿真、故障注入、SIL/HIL；覆盖时间回拨、丢包、乱序、NaN、编码器断线、急停。
2. **工程样机**：目标 MCU/SoC 交叉编译，测量最坏中断延迟、控制周期抖动、CPU/RAM、掉电恢复；完成 CAN/RS485/以太网协议和标定工具。
3. **小批量**：硬件看门狗和 STO 实测，温度/电压/EMC、长时间老化、机械极限和堵转测试；固件签名升级、A/B 回滚、版本追踪。
4. **量产**：产测夹具写入序列号和标定参数，启动自检日志可导出；冻结编译器、链接脚本、依赖和 SBOM，建立可追溯构建。

## 必须补齐的硬件相关项

- 明确电机驱动器的 enable/STO 逻辑，默认断电安全；验证 GPIO 上电毛刺不会使能。
- 对编码器、电流、温度做范围、断线和合理性检查；关键传感器采用冗余或独立比较器。
- 用独立 watchdog 监控控制任务心跳；喂狗前检查周期、故障和驱动器响应。
- 所有总线报文含设备 ID、版本、长度、CRC、序列号和超时；拒绝未知版本。
- 参数分区有 CRC、单调版本和双备份；标定失败回到安全默认值。

## 验收指标示例

控制周期 1 kHz：周期抖动 P99 < 100 us、P999 < 250 us；从命令失联到输出禁能小于 100 ms（当前默认 watchdog）；任何 fault 到驱动器 STO 的链路延迟需由示波器实测并记录。指标必须按实际机构风险重新评审，不能直接照抄示例。

## 变更与诊断

每次发布记录 git commit、工具链、配置 hash、硬件版本和测试报告。事件记录使用固定长度环形缓冲，包含单调时间、fault 位、序列号和复位原因；禁止在实时线程格式化字符串。现场升级默认保留可回滚镜像，升级前校验签名与兼容硬件版本。
