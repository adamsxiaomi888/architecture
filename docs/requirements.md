# 通用嵌入式平台需求基线

本文档把当前已确认的产品目标转成可验收的需求。它描述的是平台能力，而不是某一个智能家居、机器人或美容产品的业务实现。

## 目标与边界

平台采用 Linux 主控 + MCU 控制器的部署模型。Linux 负责应用编排、复杂算法、联网和升级协调；MCU 负责确定性控制、传感器采集、执行器输出和安全停机。应用通过能力组件组合产品，平台不按产品类别复制一套框架。

首个验证对象是一个通用执行器仿真设备：在 Linux 上运行主控和 MCU 两个独立进程，通过可控模拟通信链路交互。仿真设备必须支持两路位置执行器，其中一路模拟普通 PWM 舵机（无反馈），另一路模拟总线舵机或智能驱动器（有反馈），并能注入失联、堵转、越界、过温和传感器异常。

仿真用于验证协议、状态机、故障处理、升级流程和测试自动化；PWM/ADC 同步、FOC、电气保护、真实掉电时序和机械安全必须在目标硬件上另行验证。

## 已确认的能力

### 实时控制与执行器

- 支持舵机、智能电机驱动器和 MCU 直接驱动电机三类执行器。
- 直接驱动路径最终支持位置、速度和电流控制；FOC、电流采样、PWM 同步和硬件过流保护属于真实 MCU 阶段。
- 统一执行器接口必须表达能力差异：位置、速度、电流、反馈、使能/禁能和故障读取均可独立声明；不支持的能力返回明确错误。
- 所有实时输出经过限位、限速、超时和故障状态机；安全停机行为由设备配置并在硬件上验证。

### 传感器、参数与诊断

- 传感器接口包含采样时间、有效标志、单位、范围和错误原因。
- 参数和标定数据具备版本、CRC、默认值、双份或等效恢复机制；升级后执行版本迁移或回退。
- 日志使用固定大小记录和等级，实时任务不得格式化字符串、访问网络或写文件；事件至少包含单调时间、设备 ID、故障码、命令序号和复位原因。
- 产测覆盖通信、存储、传感器、执行器、序列号和标定结果，并生成可追溯报告。

### OTA

- 目标覆盖 Linux 应用、Linux 系统、MCU 固件以及具备升级协议的外接控制器。
- 采用 A/B 或等价的可恢复镜像策略，具备签名、哈希、硬件兼容性、版本回退保护、断点续传、断电恢复、试启动确认和失败回滚。
- 升级协调器不能让实时控制环等待网络、Flash 擦写或解密操作；升级期间执行器进入经过定义的安全状态。
- 不假设多个设备可以原子升级；必须定义兼容版本、顺序、部分成功和人工恢复策略。

### 操作系统与硬件解耦

- 核心逻辑只依赖稳定的 C 接口，不直接调用 FreeRTOS、RT-Thread、Zephyr、Linux 或芯片 SDK API。
- OSAL 抽象任务、队列、锁、时钟、延时和看门狗；HAL/设备接口抽象 GPIO、PWM、ADC、SPI、I²C、UART、CAN、Flash 和网络。
- 第一阶段以 Linux 仿真为主；随后至少接入一种 MCU RTOS。FreeRTOS、RT-Thread、Zephyr、ThreadX、NuttX、Linux PREEMPT_RT 和裸机 super-loop 属于可扩展端口，逐一实测，不以源码可编译代替实时性证明。

## 暂待确定的参数

以下内容必须在选定首块硬件前冻结：MCU/SoC 型号、RTOS、控制周期和允许抖动、执行器数量、总线物理层、Flash/RAM 预算、加密芯片或安全启动能力、OTA 入口、急停/STO 电气方案、产品认证范围，以及参数和日志的容量策略。

## 分阶段验收

| 阶段 | 交付 | 必须通过的验收 |
|---|---|---|
| 1 仿真闭环 | Linux 主控/MCU 双进程、统一执行器接口、两种舵机模型、可控时钟和故障注入 | 正常控制、过期命令拒绝、传感器异常停机、链路断开后安全动作；测试可重复运行 |
| 2 平台服务 | OSAL/HAL 边界、参数存储、日志、诊断、产测接口 | 参数损坏可恢复；重启保留有效配置；产测报告含版本和序列号；实时线程无阻塞服务调用 |
| 3 OTA | 镜像格式、签名/哈希验证、A/B 槽、断点续传、试启动和回滚 | 下载中断、校验失败、掉电、启动失败和版本不兼容均不会激活坏镜像 |
| 4 MCU 与智能执行器 | 选定 RTOS/BSP、总线舵机或智能驱动器、真实传感器 | 周期抖动、通信超时、传感器断线和硬件急停有实测记录 |
| 5 直接电机控制 | PWM/ADC/编码器、FOC 或目标控制算法、过流/过温硬件保护 | 电气和机械边界测试通过；保护链路独立于高层软件并可示波器验证 |
| 6 产品化 | 目标产品配置、生产夹具、发布追踪、长期运行和恢复测试 | 构建可追溯；批量产测可重复；升级和故障报告可现场导出 |

## 测试规则

每项需求先写自动化测试，再写实现。单元测试、接口契约测试、双进程集成测试、故障注入、硬件在环和产测分开报告。测试不得只依赖 `assert`，发布构建中也必须执行检查并报告失败编号；仿真通过不等同于硬件通过。
